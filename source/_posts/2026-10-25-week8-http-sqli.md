## 这周学了什么

### 请求到底长什么样

以前点登录就是点登录，现在至少能看见背后发出去的那一行了。

用 Repeater 改了 User-Agent，又把 GET 参数和 POST 表单各试了一遍。改完点 Send，响应一变，就知道自己动的是哪一层。

第一次看到 Send 发送成功，感觉很奇妙。

我回头看了一眼网站，页面上什么也没变，可它背后的信息已经被我改掉了。那一刻像是走进了一块全新的大陆。

这也是我第一次真切地感觉到，原来网络安全离我这么近。我想再往里走一点，看看里面到底有什么。

POST 那次印象深一点。我以前一直觉得 POST 比 GET 安全，因为参数不在网址里。看了包才明白，只是从 URL 搬到了请求体，抓包照样看得一清二楚。真正防偷看的是 HTTPS，跟用哪个方法没关系。

### Cookie

响应头里的 `Set-Cookie` 是服务器发的，浏览器存下来，下次请求再放进 `Cookie` 里带回去。就这么一个来回。

在 Repeater 里手动加了一行 `Cookie: name=admin`，响应里就显示 admin 了。CTFHub 那题是把 Cookie 里的值改成 1，自己做出来的，做完感觉有点简单。

### SQL 注入

原计划周五学 F12，结果跑去看了整数型注入。

学了 SELECT、UNION、ORDER BY，WHERE 只了解一点。`order by` 后面的数字往上加，加到报错就知道列数是几；然后 `union select 1,2,3` 把想看的东西拼到页面上。

CTFHub 的整数型注入题做出来了，flag 拿到了。不过得说清楚，是跟着教程做的。里面有一长串语句我还没真正看懂，拆开能认出每一段在干嘛，连起来就说不上了。

## 踩坑和想不通的

- 列数不对就拼不上。`order by` 那一步不能跳，跳了后面全是白试。
- 那条长语句：`union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()`。现在勉强能读出"从数据库自带的目录表里，把当前这个库的表名拼成一行拿回来"，但换成去拿列名、拿数据，我还是要照着抄。

## 开发和安全不是一回事

以前我分不清 Web 开发和 Web 安全，这周大概有数了。

开发是把功能做出来，安全是看这功能到了别人手里会变成什么样。同一个登录框，写的人想的是「怎么登进去」，我该想的是「能不能不登就进去」。
